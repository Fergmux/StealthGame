## Context

**GDD**: `design/gdd/tuning-data-config.md`
**Requirement**: `TR-tdc-002` (requirement text lives in `docs/architecture/tr-registry.yaml`; read fresh at review time); GDD CR-3 (schema row per key), CR-15

**ADR Governing Implementation**: ADR-0004: Tuning data pipeline and validator (section 2, schema generator and drift guard)
**ADR Decision Summary**: Because UPROPERTY metadata is stripped from cooked builds, an editor-only generator in `StealthGameEditor` (commandlet `StealthTuningSchemaGen`) reflects the tuning properties and writes the checked-in `StealthTuningSchema.generated.inl`, a table of `constexpr` rows with generated non-capturing get/set functions through pointers-to-member. The runtime validator reads only that table, never metadata.
**ADR Version**: 2026-10-24

**Engine**: Unreal Engine 5.8 (installed 5.8.4) | **Risk**: LOW
**Engine Notes**: No post-cutoff API. [V] `WITH_METADATA` is `WITH_EDITORONLY_DATA` (`CoreMiscDefines.h:31`) and `FField::GetMetaData` is the reader (`Field.h:946`), so the generator must run in an editor build. The commandlet base class (`UCommandlet`) and `UStruct` field iteration are pre-cutoff; confirm names against the 5.8.4 headers before use. `FFileHelper::SaveStringToFile` with `EEncodingOptions::AutoDetect` switches to UTF-16 on non-ANSI text (manifest engine note), so write the file with `ForceUTF8WithoutBOM`. No unverified [U] claim is touched.

**Control Manifest Rules (this layer)**:
- Required: The schema table is regenerated by the commandlet and committed with every tuning field change; `SchemaVersion` is bumped when the fingerprint changes (source: ADR-0004)
- Forbidden: Never read UPROPERTY metadata at runtime for ranges (source: ADR-0004)
- Required: Code lives in one of the six modules; the editor module `StealthGameEditor` may depend on the runtime modules, never the reverse (source: ADR-0007)
- Required: New code logs with `UE_LOGF` and a `LogStealth...` category (source: ADR-0007)

## Implementation Notes

*Derived from ADR-0004 section 2 and Key Interfaces:*

- Placement: `Source/StealthGameEditor/Private/Tuning/StealthTuningSchemaGenCommandlet.h/.cpp` (a `UCommandlet`, run as `UnrealEditor-Cmd StealthGame -run=StealthTuningSchemaGen`); output `Source/StealthFoundation/Private/Tuning/StealthTuningSchema.generated.inl`, included by `StealthTuningSchema.cpp` (story 038). Test in `Source/StealthGameEditor/Private/Tests/Tuning/SchemaGenDeterministicTest.cpp` (metadata-reading tests live in the editor module, ADR-0004 section 2). The editor module already exists as the MCP-toolset seed (story 003 keeps it).
- Shared generator function: put the generation in one function used by both the commandlet and the test (and later by the in-memory drift check of story 044), returning the file text; the commandlet only writes it. This avoids a second source of truth.
- Row content, as in the ADR section 2 row list: `{ KeyName, TypeTag, Accessor, Default, HardMin, HardMax, SafeMin, SafeMax, Audience, Latch, Owner, EnumValues }`. Default comes from the C++ initialiser (class default object), hard range from `ClampMin`/`ClampMax`, safe range from `SafeMin`/`SafeMax`, latch/owner/unit from custom meta, audience from the `_Public`/`_Server` struct, type from the property type. Match the row struct of story 038 field for field.
- Accessors: each row holds a pair of generated non-capturing functions through pointers-to-member (for example `&FStealthServerTuning::Crowd_Server` then `&FCrowdTuning_Server::CrowdIdleMinSec`), so a renamed field is a compile error, not silent memory corruption. Never emit `offsetof` (USTRUCTs are not standard-layout); the test scans the output text for `offsetof` and fails if found.
- Deterministic key order: the inputs require "deterministic" only. The order becomes the wire order of `NetSerialize` (ADR-0004 section 7, "schema-table order"), so decide and document it here (open). Sorting by key bytes (the F-2 hash also sorts byte-wise ASCII) is one candidate, not a mandate. Reflection field iteration order must not be relied on without checking it is stable.
- Byte-identical output: write LF line endings and UTF-8 without BOM regardless of the platform, no timestamps, no absolute paths, no machine names, and format doubles with a fixed round-trip format. Resolve project paths from `FPaths::ProjectDir()`, never the working directory (spec edge: run from a different working directory; also reordering of struct members must not change the output if the order rule is key-based).
- The generator also later emits the schema fingerprint (story 043); leave a clear extension point and do not emit it here.
- Test (T1 editor, `StealthGame.Tuning.SchemaGenDeterministic`, class `FTuningSchemaGenDeterministicTest`, flags `EAutomationTestFlags::EditorContext | EAutomationTestFlags::ProductFilter`, whole file in `#if WITH_DEV_AUTOMATION_TESTS`): call the shared generator twice, compare both texts byte for byte with each other and with the checked-in `.inl`. The test never writes the checked-in file.
- Bootstrap interplay: if a field is renamed the Foundation module stops compiling and the editor cannot host the commandlet; the escape hatch is story 042. Do not add the `STEALTH_TUNING_SCHEMA_BOOTSTRAP` handling here.
- Commit rule: the regenerated `.inl` is committed with every tuning field change (ADR-0004 guideline 8). Plan G4 does not apply (not a spike).
- Prototype: none (no `Prototype:` line in the plan).
