## Context

**GDD**: `design/gdd/tuning-data-config.md`
**Requirement**: `TR-tdc-002`, `TR-tdc-009` (requirement text lives in `docs/architecture/tr-registry.yaml`; read fresh at review time); GDD AC-3a (CR-3), CR-13, CR-15

**ADR Governing Implementation**: ADR-0004: Tuning data pipeline and validator (section 2, drift guard)
**ADR Decision Summary**: `StealthGame.Tuning.SchemaComplete` (AC-3a) regenerates the table in memory and fails if the checked-in table differs from reflection, so the generated file cannot go stale; it also checks defaults inside hard ranges, unique CR-15-suffixed names, no Config flags and only allowed types. It fails on an empty bootstrap table, so a bootstrap build can never pass CI.
**ADR Version**: 2026-10-24

**Engine**: Unreal Engine 5.8 (installed 5.8.4) | **Risk**: LOW
**Engine Notes**: No post-cutoff API. [V] metadata exists only with editor-only data (`CoreMiscDefines.h:31`), so this test lives in the editor module and compares metadata mirrors with the compiled table. Reflection flags (`CLASS_Config`, `CPF_Config`) are long-standing APIs. No unverified [U] claim is touched.

**Control Manifest Rules (this layer)**:
- Required: The schema table is regenerated by the commandlet and committed with every tuning field change; `SchemaVersion` is bumped when the fingerprint changes (source: ADR-0004)
- Forbidden: Never mark tuning types `Config`/`DefaultConfig`/`GlobalUserConfig`/`PerObjectConfig`; never read a gameplay value from ini, `Saved/Config` or a console variable (source: ADR-0004)
- Required: Every leak, parity, statistical and lint gate includes a negative control the suite detects (source: ADR-0008)
- Guardrail: Per-commit pipeline at most 10 min (source: ADR-0008)

## Implementation Notes

*Derived from ADR-0004 section 2 (drift guard) and the plan Note lines for this story:*

- Placement: `Source/StealthGameEditor/Private/Tests/Tuning/SchemaCompleteTest.cpp`, class `FTuningSchemaCompleteTest`, name `StealthGame.Tuning.SchemaComplete`, flags `EAutomationTestFlags::EditorContext | EAutomationTestFlags::ProductFilter`, whole file in `#if WITH_DEV_AUTOMATION_TESTS` (metadata tests run in the editor module, ADR-0004 section 2).
- Beyond the GDD text, the plan requires the test to also fail (a) on an empty (bootstrap) table, which is what makes a `STEALTH_TUNING_SCHEMA_BOOTSTRAP=1` build unable to pass CI (story 042 relies on this), and (b) when the checked-in table differs from the in-memory regeneration (call the shared generator function of story 041 and compare text with `StealthTuningSchema.generated.inl` as compiled in; the test never writes files).
- Checks, mapped to the AC clauses: row completeness and default-in-hard-range over `GetTuningSchema()`; unique names; suffix check against the CR-15.2 list (`Sec`, `Ms`, `Minutes`, `Cm`, `CmPerSec`, `PerSec`, `PerMin`, `Hz`, `Deg`, `Pct`, `Mult`, `Frac`, `Gain`, `Sigma`, `Exp`, `Count`, `Size`, `Limit`, `Depth`, `Asset`; enums end in `Mode`; booleans start with `b`; re-read the GDD CR-15.2 list, it wins); metadata mirrors (`ClampMin`, `ClampMax`, `SafeMin`, `SafeMax`, `Latch`, `Owner`) equal the row values; the default pin compares the Default preset asset (story 056) and the C++ initialisers (class default objects) with committed test constants copied from the GDD Canonical Tunables Default column; reflection walk over the preset class and every sub-struct allowing only `bool`, `int32`, `float` and enum properties and finding no `CPF_Config` property and no `CLASS_Config`/per-object-config class flag. The `*Asset` soft-reference keys of the Crowd epic (ADR-0004 section 1) will need an allowance when they land; not this story.
- The ADR section 2 drift guard also lists safe-range-inside-hard-range and the AC-15 name allowlist; those are not in AC-3a. Safe-range checks are reported by `SafeRangeLint` (story 094) and the allowlist is story 091. Do not add them here.
- Negative controls (ADR-0008 section 3, required): a seeded default outside its hard range, and an empty table, each fed to the check function (the check logic must be callable on a supplied row view, not only on `GetTuningSchema()`), each detected as a failure by the enclosing test (the story 010 helper `FStealthNegativeControl` in `Source/StealthFoundation/Public/Server/Testing/StealthNegativeControl.h` is the intended tool, G1 path; story 010 is not in this story's dependency list, so confirm it has landed before starting or add it as a dependency).
- Test placement caution: the test needs the Default preset asset (story 056) to exist; load it by explicit path and do not save or resave it.
- Prototype: none (no `Prototype:` line in the plan). The prototype's values are never read here; defaults are pinned to the GDD by committed constants.
