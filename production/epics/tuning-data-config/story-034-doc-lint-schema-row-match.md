## Context

**GDD**: `design/gdd/tuning-data-config.md`
**Requirement**: `TR-tdc-002` (text lives in `docs/architecture/tr-registry.yaml`; read fresh at review time); GDD AC-3b (CR-15), third bullet (schema half)
*(Requirement text lives in `docs/architecture/tr-registry.yaml` — read fresh at review time)*

This is the schema half of AC-3b's third bullet. The generated schema table (story 041's `StealthTuningSchema.generated.inl`) holds a row per tuning key; the owner GDD Tuning Knobs rows must agree with it on default, hard range, audience and latch, which is also how a widened hard range is caught: widening a range is a code change plus a GDD change (CR-3), and the lint compares the GDD row with the regenerated schema row (ADR-0004 section 2). Schema rows for non-TDC owners arrive with their own epics (a decision recorded in the decision log), so most owner GDDs have no schema rows yet. Rather than failing the lint for all of them or exempting them silently, a pending-owner baseline file lists the owners whose epics have not yet registered a sub-struct; the baseline may only shrink, and each entry cites its owning epic. When story 096's condition is met (the baseline is empty) every owner is checked.

**ADR Governing Implementation**: ADR-0004: Tuning data pipeline and validator
**ADR Decision Summary**: The schema is declared once on the UPROPERTYs and compiled into a checked-in generated table; the design-doc lint (AC-3b) compares each owner GDD row with that table; the lint reports observations and never edits a GDD or a value.
**ADR Version**: 2026-10-24

**Engine**: Unreal Engine 5.8 (installed 5.8.4) | **Risk**: LOW
**Engine Notes**: No engine API at runtime: a build-time script that reads the generated `.inl` as text (Python, if used, only as a build-time tool run with `python -I`). The row layout it must parse is defined by story 041 (ADR-0004 gives the row fields `{ KeyName, TypeTag, Accessor, Default, HardMin, HardMax, SafeMin, SafeMax, Audience, Latch, Owner, EnumValues }`); the exact text layout of the file is not known until that story lands. Nothing here is an unverified engine claim.

**Control Manifest Rules (this layer)**:
- Required: lints and analysis scripts emit observations only; pass/fail lives in the gate script — source: ADR-0008
- Required: the schema table is regenerated by the commandlet and committed with every tuning field change; `SchemaVersion` is bumped when the fingerprint changes — source: ADR-0004
- Forbidden: never silence a safe-range lint finding by editing the baseline without citing a GDD change request or OQ (the same shrink-only, cited-entry discipline applies to this baseline via G3) — source: ADR-0004
- Forbidden: never make a gate depend on the MCP toolsets or Python editor scripting — source: ADR-0008

## Implementation Notes

*Derived from ADR-0004 section 2 and the global amendments G3 and Amendments 2:*

- **Files.** `tools/ci/lint/knob-lint-schema.*` (extension open; the plan's `TOOLS/lint/`) and `tools/ci/lint/knob-schema-pending.txt`. Records come from story 029; schema rows come from story 041's generated table.
- **Comparison.** For each owned key of a non-pending owner: find the schema row by key; report a missing row, and report each differing field (default, hard range, audience, latch) separately, naming key and field. The AC lists those four fields; whether the safe range is also compared is not stated (the spec says "default/range/audience/latch"): open, and if included the script header says so. The same normalisation questions as story 033 (numeric equivalence, range formatting) apply; reuse that decision where possible.
- **Pending file format.** One entry per line, `<owner-gdd-path> | <epic-slug>`, for example an owner GDD under `design/gdd/` with the slug of its owning epic. Valid slugs: only `tuning-data-config` exists under `production/epics/` at writing, so whether a slug must name an existing epic directory is open; the AC requires only that each entry cites its owning epic, and an entry without a slug is malformed and fails.
- **Shrink-only rule (G3, Amendments 2).** Compare the working-tree baseline with its content at the base ref: `HEAD` when run from the pre-commit hook; the push's before-SHA (`github.event.before`, else `HEAD~1`) when run in CI; with no remote, `HEAD`. Any entry absent at the base fails (an owner added to the list). Creation of the file at the first base-less commit is exempt. The reference is the previous commit of the baseline, not `origin/main`, because in trunk-based CI on a push to main `origin/main` already equals `HEAD`, so an added entry would never be detected (the gap the qa-lead spec found). An entry for an owner that has since registered its sub-struct (so it now has rows) must be removed: report it.
- **Initial content.** The pending file starts with every owner GDD that has knob rows but no schema rows yet (all except the TDC-owned keys, the eight canonical keys and the TDC constant, whose rows story 040 and 041 provide). The first creation is exempt from the shrink rule.
- **Later effect.** Story 096 unblocks when this baseline is empty; each owner epic removes its own entry when it registers its sub-struct.
- **Selftest (G2 a).** In a temporary repository with a base commit: matched keys (silent); a key with a differing default, range, audience or latch (reported per field); a pending-listed owner (exempt); an owner added to the list (fails, absent at base); a malformed entry without a slug (fails); initial creation (exempt); no remote falls back to `HEAD`; a stale entry for a registered owner (reported).
- **Wrapper (G2 b).** `StealthGame.Build.KnobLintSchema` in `Source/StealthFoundation/Private/Tests/Build/KnobLintSchemaTest.cpp` runs the selftest through `FPlatformProcess` and asserts exit code and observations. Foundation (story 001) is reached through story 041's chain.
- **Prototype.** None.
