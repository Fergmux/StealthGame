**ADR Governing Implementation**: ADR-0019: Informant lifecycle and crowd-pawn takeover (§4.3), with ADR-0014 §7.3 (widening levels, per-frame pick guard) and ADR-0002 §4 (inline due items)
**ADR Decision Summary**: `RespawnRequestSeq` is allocated once per respawn request and reused on every retry, so the per-request stream continues and widening is keyed by the request: level 0 until `RespawnStarvationSec` after `PickStartServerTime`, level 1 (the region widened to 2 × `InformantRespawnPathCm`, still cut by the nearer-anchor rule) until twice that, then level 2 (the city minus the enemy team's respawn region). A retry is `ScheduleAt(now + EmergenceRetrySec, TimerFired(InformantRespawn, same payload))`; a `Deferred` pick or an excluded candidate re-schedules with a due time strictly greater than the drain's start (`ServerNow + 1 ms`). The unseen test is never relaxed, a bound pawn is never taken, no pawn is spawned; past level 2 the participant keeps waiting and `RespawnStarved` is logged once per request. Round's `LateJoinTakeoverTimeoutSec` fallback never applies to informants.
**ADR Version**: 2026-10-24

**Engine**: Unreal Engine 5.8 (installed 5.8.4) | **Risk**: MEDIUM
**Engine Notes**: No engine API. Widening level and `RespawnStarved` come from LSC (`FRespawnPick.WideningLevel`, a confirmation requested of ADR-0014); Penalty only drives retries and reports. The one-pick-per-frame guard is LSC's budget (ADR-0014): do not add a second guard in Penalty.

**Control Manifest Rules (this layer)**:
- Required: retries reuse the request's `RespawnRequestSeq`; widening comes only from LSC — source: ADR-0019
- Forbidden: never relax the unseen test; never spawn a pawn for a respawn; never use an engine timer in Penalty — source: ADR-0019
- Guardrail: at most one pick per frame (LSC budget); retry items are heap items, not ticks — source: ADR-0014, ADR-0019

A starved informant keeps waiting on the neutral view with a static "Returning" (the UI forbids a widening level or count-up); the only residuals are the accepted PEN-R14.3 informant-side hint. This story covers the retry timing, the strict-later rule that prevents an inline re-run in the same drain, and the log-once rule.

**Prototype replaced:** none (the prototype's `RespawnInformant` picked any free crowd pawn immediately and gave up with a fixed fallback).

## Implementation Notes

*Derived from ADR-0019 Decision §4.3 and PEN-R10:*

Add retry bookkeeping to the commit (story 012): `PickStartServerTime` is set when the item first fires (state `Picking(0)`), `LastWideningLevel` is stored from each `FRespawnPick`, and `RespawnRequestSeq` is allocated once per request in `ScheduleRespawn`/readmission (story 009/010) and never regenerated by a retry. Three retry kinds:
- `None` -> regular retry at `now + EmergenceRetrySec`; clears the request's exclusion set (a transiently ineligible pawn can return).
- `Deferred` (the per-frame guard) or an excluded candidate (steps 3-5 of story 012) -> next-frame retry at `ServerNow + 1 ms`, strictly greater than the drain's start, because an inline item due at or before now would run in the same drain (ADR-0002 §4) and break the one-pick-per-slot rule. A `Deferred` consumes no widening time.
- All retries reuse the same payload `{P, RoundEpoch, RespawnRequestSeq}` so the LSC stream per request continues rather than repeating.

Widening is LSC's (the 10 s / 20 s thresholds are `RespawnStarvationSec`); Penalty reads `WideningLevel` from the pick and stores it for the `InformantRespawn` row. `RespawnStarved` is LSC's Event Log row; the test asserts it appears exactly once past both widenings and that Penalty never writes a second one. Past level 2 Penalty keeps scheduling `EmergenceRetrySec` retries indefinitely (no timeout, no view-only fallback); assert Round's `LateJoinTakeoverTimeoutSec` path is never invoked for an informant (a spy on Round's fallback).

Use a fake LSC gateway that returns `None` for N calls then a pawn, and records the `RequestSeq`, widening level and frame of each call. Boundary values (10.0 s, 20.0 s) are the point of the test, as in the AC.

## QA Test Cases

*Written by qa-lead at story creation. The developer implements against these — do not invent new test cases during implementation.*

- **AC1** (AC-NKP-14, `StealthGame.Penalty.StarvationWidening`)
  - Given: a fake clock and a fake LSC that returns `None` with `WideningLevel` 0, then 1 after 10 s and 2 after 20 s.
  - When: a respawn is due and the clock advances to 60 s.
  - Then: `PickRespawnPawn` is called every `EmergenceRetrySec` with the same `RequestSeq`; the stored level follows 0, 1, 2 and retries continue past 20 s; when the fake finally returns a pawn the `InformantRespawn` row carries `WideningLevel = 2`; no pawn is spawned and Round's view-only fallback is applied 0 times.
  - Edge cases: Penalty writes no `RespawnStarved` row (the real-LSC integration run asserts it once per request); the level never decreases.
- **AC2** (derived, `StealthGame.Penalty.RetryBookkeeping`)
  - Given: a fake LSC script of `Deferred`, then a pick excluded by the pre-check, then `None`, then `Picked`.
  - When: the request retries.
  - Then: every call carries the same `RespawnRequestSeq`; the `Deferred` and excluded retries are scheduled at `ServerNow + 1 ms`, strictly after the drain start and never inline, and leave `PickStartServerTime` and the stored level unchanged; the `None` retry is scheduled at `EmergenceRetrySec` and its `Exclude` set is empty.
  - Edge cases: the exclusion set survives consecutive + 1 ms retries and clears only on a regular retry; a new request gets a new seq.
