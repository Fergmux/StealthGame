# Spike S9: the explicit channel close lands at the deadline and the channel stays closed, 2026-10-25

> **Story:** `production/epics/information-visibility-policy/story-004-spike-s9-cull-latency-and-explicit-channel-close.md`
> **Governs:** ADR-0003 §5.3-5.5 (E2, E5, E10, E15), condition S9 · **Engine:** UE 5.8.4 Development editor binary in game mode, legacy `IpNetDriver` (Iris off)
> **Verdict:** **PASS** — under StealthLeak1 and StealthLeak2 with 3 clients, every denied connection's channel closed in the first server frame at or after the grid deadline (late by ≤ 2.5 ms, inside one server frame), all same-frame culls closed in one server frame on one boundary, no channel re-appeared on any denied connection for 62 s, no forced-relevant request occurred, and the E15 assertion holds with the design's 10 connections. **CONCERNS (recorded, not failing):** L27 could only be staged by forcing the base relation (stock characters cannot stand on a character); the E15 assertion fails if it reads the engine's default `GameSession.MaxPlayers` (16).


- 1 listen host + 3 client processes (`UnrealEditor.exe -game -nullrhi`), one machine, profile applied on every process (100 ms each way). Host frame rate ~300 fps median (uncapped).
- Throwaway spike code in the production rule shape (`Source/StealthTestHarness/Private/Scenarios/StealthHarnessScenarioS9.cpp`): per-pawn cull record `{State (Visible, CullPending, Culled), CommitServerTime, CullDeadline, Reason}`; deadline on a global grid of multiples of `1 / PawnNetUpdateHz` (15 Hz) from the round's Active entry, first point at or after `CommitServerTime + ConcealCullDelayMs` (250 ms); an `FTickFunction` in `TG_PostUpdateWork` moves due records to `Culled` and calls `FindActorChannelRef` → `Close(EChannelCloseReason::Relevancy)` for every denied connection in that frame.
- Relevancy: `AStealthCharacter::IsNetRelevantFor` delegates to a non-Shipping spike hook (`Source/StealthGame/Public/Server/Spikes/StealthSpikeHooks.h`); the scenario's override **replaces Super entirely** (visible and pending pawns relevant; a culled pawn relevant only to allies), resolves the viewer from `RealViewer` through a server-side PlayerController → team cache, and denies an unknown viewer for a culled subject.
- Subjects: three crowd pawns (denied for all 3 connections) and C1's pawn (denied for the other team) committed in one frame; a fifth crowd pawn is the negative control (override only, no close).
- Timeline after the deadline: +5 s L27a (C2's pawn held on a culled crowd pawn), +20 s L27b (a culled crowd pawn held on C3's pawn), each for 10 s; +35 s both denied viewers parked 90 cm from culled subjects; observation ends at +62 s.
- Measurement: every server frame, `FindActorChannelRef` for each (subject, denied connection) and (subject, allowed connection), and the subject's `FNetworkObjectInfo::ForceRelevantFrame`; on clients, pawn destroy/spawn with the shared QueryPerformanceCounter clock.

## Findings that change or confirm the ADRs

1. **E10 confirmed [V runtime]:** with the override returning false, the closed channel stayed closed for 62 s, including with denied viewers standing next to, on top of and under culled pawns; no relevancy-timeout or forced-relevant re-creation.
2. **E2 confirmed [V runtime]:** without the explicit close, the channel lingered 4.6-5.2 s (relevancy timeout) — a timing channel. The explicit close is load-bearing.
3. **L27 (CONCERNS):** stock `ACharacter` capsules are not walkable bases (`CanCharacterStepUpOn = ECB_No`); a pawn dropped onto another slid off within 0.5 s both ways, also with `ECB_Yes` set on the server. The relation was therefore forced (MOVE_None, `SetBase` every server frame) to exercise the case; the override never consults `IsBasedOnActor`, so the outcome is by construction, and the forced relation did not re-open a channel. Whether a real pawn-on-pawn base can occur with the production pawn is a SCL question (ADR-0010 collision setup), not an S9 one.
4. **E15 input (CONCERNS):** the assertion holds only with `MaxConnections` = 10 (the design's 5 v 5). The engine's `AGameSession::MaxPlayers` defaults to 16, which fails it. Production must either pin `[/Script/Engine.GameSession] MaxPlayers=10` (a Config edit) or define the assertion on the design constant; the production story (023/035) decides.
5. **Client loss latency** = server close + one-way lag + one client frame (≈ 104-113 ms at PktLag 100); the cull carries no client acknowledgement wait.

## Limits

- One machine; uncooked Development editor binary; prototype pawn and the spike hook (production re-proof: stories 023-025).
- Host uncapped (~300 fps): "± one server frame" is measured at ~3 ms frames; at a 60 fps host the same rule gives ≤ 16.7 ms.
- S10 (re-open behaviour and NetGUID) and S12 (cull delay vs L99) are separate spikes and were not exercised.
