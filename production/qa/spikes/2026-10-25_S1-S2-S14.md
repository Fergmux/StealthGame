# Spikes S1, S2, S14 (ADR-0001) and editor follow-ups, 2026-10-25

> **Owner:** phase-2 UE 5.8 engineering agent · **Engine:** UE 5.8.4, legacy `IpNetDriver` (Iris off) · **Map:** `L_Prototype`
> **Gates:** ADR-0001 Status conditions (S1, S2, S14), Engine Compatibility E12/E14/E17, §8 fallback
> **Verdicts:** S1 **PASS for the three pointers, FAIL for full pawn parity** (two non-pointer differentiators) · S2 **PASS** within the testable scope (travel and rejoin not testable) · S14 **PASS** for every possession path the prototype has (rejoin and PawnRecovery not testable)

## 0. Method and tooling

**Spike switch.** Console variable `stealth.Spike.IdentityTrims` (bitmask, default 0). Net drivers read it when they build replication layouts, so it is set before a PIE session starts.

| Bit | Effect | ADR-0001 section |
|---|---|---|
| 1 | `APawn::PlayerState` (by name), `APawn::Controller` and `AActor::Owner` set to `COND_OwnerOnly` on `AStealthCharacter` | §4.1 |
| 2 | `APlayerState` trims from the §4.3 table, and PlayerState `Owner` set to `COND_OwnerOnly` | §4.3 |
| 4 | Strict allowlist: prototype `Team` and `LifeState` set to `COND_OwnerOnly` | §4.3 |
| 8 | Fallback: pawn `PlayerState`, `Controller` and `Owner` disabled (this overrides bit 1) | §8 |

**Code** (throwaway; compiled out of Shipping with `#if !UE_BUILD_SHIPPING`; left in place for the orchestrator to decide on):
- `Source/StealthGame/Private/Spikes/StealthIdentitySpike.h` and `.cpp` contain:
  - the cvar and the trims;
  - the probe console commands `stealth.Spike.Dump`, `DumpAll`, `RepMap`, `TakeOver <PlayerIndex>` and `AutoMove <s>`;
  - logging of PlayerState spawn and destroy.
- `Source/StealthGame/Private/Spikes/StealthMeasureSpike.cpp` adds `stealth.Spike.MeasureMesh <paths>` (reference-pose bones and bounds).
- Hooks: three lines each in `Source/StealthGame/Private/StealthCharacter.cpp` and `StealthPlayerState.cpp`, both guarded by `#if !UE_BUILD_SHIPPING`. Each hook calls the spike after the class's own `DOREPLIFETIME`s.
- Snapshot taken before the edits: `_snapshots/2026-10-25_spikes-S1-S2-S14/`. Build log: `production/qa/logs/2026-10-25_build_spikes*.log`.
- Headless regression with the hooks compiled in (cvar 0): `Automation RunTests ^StealthGame.` gave 12/12 Success, EXIT CODE 0 (`production/qa/logs/2026-10-25_headless_spikes.log`).

**Runs.** All runs were 3-player PIE: a listen host and 2 clients, in one process, with real UDP `IpNetDriver`s on loopback. Network emulation applied on the server: 50-70 ms each way and 1 % loss each way, which showed as a reported ping of about 246 ms. This is close to the `LeakNetProfile` in ADR-0001 but is not that profile exactly.

| Run | Trims | What was exercised |
|---|---|---|
| R0 | 0 (baseline) | Join, round start (`RestartPlayer`), `TakeOver` of a crowd pawn, AI hand-over of the former body, kill, then round over and restart |
| R7 | 7 | Same as R0 |
| R7b | 7 | Takeover plus **real keyboard input** (Win32 `keybd_event` W) on the taken-over body, kill of a team-0 player, informant respawn (`RestartPlayer`) |
| R14 | 14 (bits 2+4+8) | §8 fallback: takeover and `AutoMove` |

**Wire evidence method (S1).** `LogRepProperties=VeryVerbose` and `LogNetTraffic=Log` on the legacy driver.
- **Send side (server).** Each `Replicate <actor>, bNetInitial, bNetOwner` line is followed by `SendProperties_r: Parent=N`. This gives the parent indices placed in each per-connection changelist, split by owner and non-owner.
- **Receive side (clients).** Each `Actor <full path incl. UEDPIE_n>` line is followed by `ReceiveProperties: Owner=<class>` and `ReceiveProperties_r: Parent=N`. This gives the parent indices each client actually read.
- **Decoding.** `stealth.Spike.RepMap` decodes a parent index to a property: it is the `ClassReps` index (verified: `RepLayout.cpp:6104-6117`, `check(ParentHandle == i)`).
- **Server truth.** The `stealth.Spike.Dump` NetGUIDs map client actors to server truth: which pawn is a player and which is an NPC at each dump, and which pawn is locally controlled on each client.
- **Analyzers:** `production/qa/spikes/2026-10-25_tools/s1_analyze.py` and `ps_analyze.py`. Outputs: `production/qa/logs/2026-10-25_S1_{R0,R7}_analysis.txt`. Extracts (gzip, filtered to rep/probe lines): `production/qa/logs/2026-10-25_S1_{R0,R7}_rep-extract.log.gz`.

**Limits of the method:**
- (a) It runs in a single process, though each PIE instance has its own net driver and GUID cache. It is not multi-process and not multi-machine.
- (b) It compares at property-handle level: which replicated properties reach a connection, and how often. It is not a bit-exact bunch comparison. Bunch sizes and the content of property values are not compared.
- (c) Attribution depends on the log order of the game thread.
- (d) The legacy driver uses shared serialization (`WriteSharedProperty`). The per-connection `SendProperties_r` lines still list the parents.
- (e) Iris was not tested (it is pinned off).
- (f) Logging slowed the listen host to about 3 fps. This changes timing but not which properties replicate.
- (g) Only 3 players, so there are at most 2 non-owner observers.
- (h) The analyzer files a client's own *pre-round* pawn under kind "?". That pawn existed before the first dump and was destroyed by `StartRound`. The send-side split is the authoritative measure for that pawn.

## 1. S1: wire parity (legacy driver)

**Three pointers (`PlayerState`, `Controller`, `Owner`) on pawns:**

| | Sends to non-owner channels (server) | Sends to owner channel | Non-owner receipts (clients) |
|---|---|---|---|
| R0 baseline | Controller 97, Owner 97, PlayerState 17 | 7, 7, 7 | Player pawns got PlayerState, Controller and Owner. NPC pawns got Controller and Owner (39 each per client) |
| R7 trims | **0, 0, 0** | 5, 5, 5 | **0** for every pawn either client ever saw. The only hits are each client's own pre-round pawn (kind "?", see limit h) |

- **Result: PASS.** Under §4.1 no non-owner connection receives any of the three pointers, for player pawns or NPC pawns, across spawn, round restart, takeover, AI hand-over and kill.
- Side benefit: with the trims on, crowd AIControllers are never exported and get NetGUID 0. In the baseline the server allocated a GUID for every `StealthNpcController` because pawn `Owner` and `Controller` referenced it.
- `PlayerState->GetPawn()` is null for other players on every client (dump `pawn=null`).

**Full replicated-property set, non-owner view, union over pawns (R7):**

| Kind (server truth) | Parents received |
|---|---|
| NPC | 4 RemoteRole, 6 ReplicatedMovement, 8 Role, 9 Instigator, 14 ReplicatedBasedMovement, 21 bProxyIsCharacterMovementActive, 22 ReplicatedMovementMode, 26 AppearanceIndex, **29 bConcealed** |
| Player | 4, 6, 8, 9, 14, 21, 22, 26, **27 bDying** |
| Player in a taken-over body | 4, 6, 8, 9, **10 RemoteViewPitch16**, 14, 21, 22, 26, 29, **31 HeldUntilServerTime** |

- 27, 29 and 31 are gameplay events (a death, an NPC in a bush, a struck player). They are prototype pawn fields that the ADR-0001 Migration Plan already replaces.
- **`RemoteViewPitch16` (parent 10) is a systematic differentiator.** It reached non-owners only for player-controlled pawns, in R0 and in R7. AI pitch never changes from 0, so the property is never dirty for NPCs. ADR-0001 §2 already requires `PreReplication` to write `RemoteViewPitch16` from `HeadLook` for every pawn. The spike confirms that requirement is load-bearing.
- **`CBP_SandboxCharacter.CharacterInputState` (parent 33, `COND_SkipOwner`) is a second differentiator, found by static analysis and not yet in ADR-0001.**
  - It is set only by the owning client's Server RPC `UpdateInputState_Server`, which fires on the `IA_Walk`, `IA_Sprint`, `IA_Strafe` and `IA_Aim` input events.
  - The NPC AIController never sets it, so the value stays at its default for NPCs.
  - Whenever a player toggles walk, sprint, strafe or aim, every other client receives a property that NPCs never send.
  - The runs did not toggle these inputs, so it did not appear on the wire.
  - It also drives `UpdateRotation_PreCMC` and `GetDesiredGait`, which are visible on simulated proxies.
- `CBP_SandboxCharacter.TraversalResult` (`COND_SimulatedOnly`) is set only through the player's `Traversal_Server` RPC. It has the same issue for any NPC that never traverses.
- **Result: FAIL for whole-pawn parity in the current prototype.** None of these differentiators is caused by the trims.

## 2. S2: PlayerState trims (bits 2+4)

**What reaches the clients (`ps_analyze.py`, R0 compared with R7):**

| | Another player's PlayerState | Own PlayerState |
|---|---|---|
| R0 | Owner, PlayerId, **CompressedPing ×43**, StartTime, UniqueId, PlayerNamePrivate, Team, LifeState (plus Role and RemoteRole) | Owner, PlayerId, StartTime, UniqueId, PlayerNamePrivate, Team, LifeState |
| R7 | **PlayerNamePrivate only** (plus Role and RemoteRole) | Owner, PlayerId, UniqueId, PlayerNamePrivate, Team, LifeState |

On clients, other players' PlayerStates show `PlayerId=0 ping=0 team=255 uniqueIdValid=0 owner=null pawn=null`. The allowlist works as §4.3 intends.

**Side effects observed:**
- **Login:** all 3 players logged in on every run. `PlayerArray.Num()` was 3 on every client.
- **HUD:**
  - Team name, ACTIVE/INFORMANT, defence cooldown and civilians killed all render from the owner-only fields (`2026-10-25_S14_R7b-trimmed-client2-informant-respawned.png`).
  - The prototype has no scoreboard.
- **Teammate markers:** they disappear. `AStealthHUD::DrawTeammateMarkers` filters with `IsNpc()`, which is `PlayerState == null`, and `GetTeam()`, which reads the pawn's PlayerState. Every remote pawn now reads as an NPC. This is the expected break: the prototype derives identity from presentation, and C-TeamView (§5) replaces it. The evidence is the dumps (`IsNpc()=1` on every remote pawn on both clients). The screenshots `2026-10-25_S2_R7-trimmed-*watching-teammate.png` are **inconclusive**, because the debug teleport did not reliably frame the teammate. The baseline screenshot `2026-10-25_S2_R0-baseline-client2-watching-teammate.png` shows the marker before the trims.
- **Other prototype presentation paths that break the same way:**
  - `UpdateConcealmentVisibility` hides concealed *teammates* too.
  - `FindAssassinationTarget` no longer skips teammates on the client. This is a client filter only, and the server rule check is unchanged.
- **Ping:** `SetShouldUpdateReplicatedPing` is **protected** on `APlayerState` in 5.8.4 (`PlayerState.h:298`, under a protected block), so the spike could not call it from outside the class. `CompressedPing` is disabled by bit 2, so the wire result is the same. Production must set `bShouldUpdateReplicatedPing = false` inside `AStealthPlayerState`. It is an `EditDefaultsOnly` UPROPERTY, so the constructor can set it.

**Frozen PlayerArray:**
- No PlayerState was created or destroyed in a round across takeover, kill, informant respawn and round restart (`[SpikePS]` lines).
- A client disconnect in R7 destroyed its PlayerState, and the other client's `PlayerArray` shrank. The disconnect was a tooling artefact (see §5). It confirms that §4.4 needs the ADR-0005 retained-PlayerState mechanism, which the spike does not implement. This is not a side effect of the trims.

**Not testable in the prototype:**
- seamless travel (the prototype has no travel);
- rejoin and inactive PlayerStates;
- online-subsystem registration beyond the NULL subsystem (no errors with the NULL subsystem);
- voice.

## 3. S14: owner-only pointers and possession

**Static audit: does anything read another pawn's `PlayerState`, `Controller` or `Owner` on a client?**

- **Source/** (prototype; all already listed in the ADR-0001 Migration Plan):
  - `AStealthCharacter::IsNpc`, `GetTeam`, `IsInformant`, `IsActiveAgent` and `IsTeammateOfLocalViewer` read the pawn's PlayerState.
  - They are called on clients by `Tick` → `UpdateConcealmentVisibility`, by `FindAssassinationTarget` and by `AStealthHUD::DrawTeammateMarkers` (which also uses `GetStealthPlayerState()->GetPlayerName()`).
  - `AStealthGameMode` reads are server-only.
- **Sample Blueprints.** Method: byte grep of `Content/**/*.uasset`, then MCP `BlueprintTools.find_nodes` and `read_graph_dsl`.
  - **No `GetPlayerState` or `IsPlayerControlled` anywhere.**
  - `CBP_SandboxCharacter` reads `GetController` only on its own pawn, in `SetupInput` and `SetupCamera`. Both are reached from `EventPossessed` → `EventPossessed_Client` (an owner-client call).
  - `GetOwner` in `BP_AnimNotify_FoleyEvent`, `BP_NotifyState_MontageBlendOut` and `PreCMCTick` is the component's owning actor, not `AActor::Owner`.
  - **E14 is confirmed for PlayerState and Controller.**
- **Role-keyed branches** (these do not read identity pointers, but they matter for parity):
  - `CBP_SandboxCharacter.CanSprint` selects pending input or CMC acceleration with `IsLocallyControlled`.
  - `ABP_SandboxCharacter` uses a property-access `SandboxCharacter.IsLocallyControlled`.
  - On the **listen host**, AI-controlled pawns are locally controlled and remote players are not. This is a host-visible animation and gait difference between NPCs and players.
  - `EventBeginPlay` binds `OnCharacterMovementUpdated` only when `GetLocalRole == SimulatedProxy`. That role is captured once at BeginPlay, so after a takeover a body keeps the binding of its old role.

**Runtime with trims 7 (R7, R7b):**

| Path | Result | Evidence |
|---|---|---|
| Initial possession, `ClientRestart`, camera | OK | Owner pawn has local Controller, PlayerState and Owner. HUD correct |
| Round restart (`RestartPlayer`) | OK | R7 dumps |

| CMC `ServerMove` routing after takeover | OK. **Real keyboard W** moved the body about 410 uu on client and server | R7b dumps `R7b-takeover-before-keys` and `R7b-takeover-after-keys` |
| AI hand-over of the former body | OK (the NPC controller wanders it) | Location changes in the dumps |
| Kill, then informant respawn (`RestartPlayer`) | OK, input works | `2026-10-25_S14_R7b-trimmed-client2-informant-respawned.png`, `AutoMove` |
| Stale state on the previous owner | **Confirmed.** The former body keeps `PlayerState` and `Owner` on the old owner's client (`Controller` is cleared). `IsPlayerControlled()=1` and `IsNpc()=0` there | `pie=2 SUMMARY nonLocalWithAnyLink=1 (PlayerState=1 Controller=0 Owner=1)` |
| Rejoin, PawnRecovery | Not testable: the prototype has neither | — |

**§8 fallback (R14):**
- Movement and takeover work. `ClientRestart` still sets the owner's `Pawn->Controller` with Controller replication disabled.
- No stale state is left on the old body.
- The owner's own pawn has `PlayerState=null` and `IsPlayerControlled()=false`. Any owner-side code that reads the pawn's PlayerState stops working; in the prototype, `IsActiveAgent` gates assassinate, defend and interact.

## 5. Incidents during the run

- **Live Coding deadlock.** `LiveCodingToolset.CompileLiveCoding` hung the editor game thread: no LiveCodingConsole process existed and the editor was not responding after 5 minutes. The editor was killed; nothing was unsaved. Rebuilt with `Build.bat` and relaunched. Avoid Live Coding through MCP when a new `.cpp` file is added.
- **Sample Blueprint left dirty after MCP graph reads.** After `BlueprintTools.read_graph_dsl` and `find_nodes` on the sample BPs, which raised "Cycle detected ... RInterpTo" and "Cannot cast K2Node_Composite" errors, the next PIE recompiled `CBP_SandboxCharacter` in memory and failed: "more than one function with the same name OnCharacterMovementUpdated_E...". The editor then showed a modal "Blueprint Asset Compilation Error" dialog (`production/qa/evidence/2026-10-25_tooling_cbp-compile-error-after-mcp-graph-read.png`). The editor was killed without saving. `git status Content` is clean and the hash and timestamp of `CBP_SandboxCharacter.uasset` are unchanged. **Rule: do not run `read_graph_dsl` or `find_node_types` on sample Blueprints in a session that later starts PIE.**
- **Client 2 kicked at round restart in R7.** This is a tooling artefact. `stealth.Spike.TakeOver` left a crowd pawn possessed by a PlayerController while that pawn was still in `AStealthGameMode::CrowdNpcs`. `CleanupRoundActors` then called `Destroy()` on the pawn's controller, which was the client's PlayerController (`APlayerController::DestroyNetworkActorHandled` → `GracefulClose`). This is not caused by the trims. It is a reminder that round cleanup must not assume a body's controller kind (ADR-0010 and ADR-0005).

## 6. What ADR-0001 should change

The ADR owner applies these; this agent did not edit docs/architecture.
1. **E17 / §4.3:** `SetShouldUpdateReplicatedPing` is **protected** [V `PlayerState.h:298`]. Specify `bShouldUpdateReplicatedPing = false` in the `AStealthPlayerState` constructor.
2. **E14 → [V] for PlayerState and Controller.** The sample BPs contain no `GetPlayerState` or `IsPlayerControlled`, and `GetController` is read on the own pawn only. Add the role-keyed branches as a new item: `CanSprint` and the ABP property access `IsLocallyControlled` make AI and remote-player pawns animate differently **on the listen host**. Route this to ADR-0013 ANIM-V3 and the §1 rule "no branch on `IsLocallyControlled` for anything observable".
3. **§2 / requirement "identical raw-bunch class":** add the sample BP replicated variables `CBP_SandboxCharacter.CharacterInputState` (SkipOwner) and `TraversalResult` (SimulatedOnly) to the parity list and the IVP allowlist. NPCs must drive them through the same command path (ADR-0011), or the pawn must derive them server-side for every pawn. The `RemoteViewPitch16` mechanism in §2 is confirmed necessary: S1 observed it as a player-only property.
4. **E12 → [V runtime]:** re-delivery to the new owner is confirmed. The stale `PlayerState` and `Owner` on the old owner's former body are confirmed, and on that client `IsPlayerControlled()` returns true. Keep the owner-local cleanup in §4.1.
5. **AC-IVP-37 canary:** check the **whole parent set** per non-owner connection, not just the three pointers. The analyzers in `production/qa/spikes/2026-10-25_tools/` are a starting point. The `stealth.Spike.RepMap` readback (CDO `GetLifetimeReplicatedProps` → conditions) is a workable form of the harness boot assertion: it showed all by-name resets in effect.
6. **ADR-0010 note:** sample setup that depends on role (`GetLocalRole` at BeginPlay) must be re-run on role change after a takeover.

**Recommended ADR-0001 status:**
- Keep it **Accepted (conditional)**.
- S1, S2 and S14 have **reported**:
  - the §4.1 and §4.3 mechanisms work on the legacy driver;
  - the §8 fallback is not triggered (the fallback was also exercised and works);
  - amendments 1-3 are required before implementation depends on the ADR.
