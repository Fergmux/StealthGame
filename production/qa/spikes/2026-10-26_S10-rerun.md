# Spike S10 re-run: re-open guard, lost-pawn repair, pose warm-up and the ADR-0002 clock, 2026-10-26

> **Story:** `production/epics/information-visibility-policy/story-056-s10-fix-implementation-and-rerun.md` (TR-ivp-004)
> **Governs:** ADR-0003 amendment "S10 resolution 2026-10-25" (S10-R2..R8, gate S10-R7), ADR-0002 §9 (amendment "S10 resolution") · **Engine:** UE 5.8.4 Development editor binary in `-game`, legacy `IpNetDriver`, 60 fps cap, `StealthLeak1` / `StealthLeak2` on every process, 3 clients, 30 NPCs
> **Baseline:** `production/qa/spikes/2026-10-25_S10.md` (FAIL: in-flight race loses ~1-2 % of race re-opens; collapsed first frame; pose time ~150 ms late on the engine clock)
> **Verdict:** **PASS** — every S10-R7 condition holds on the gate runs `s10r-l1b` (StealthLeak1, render client) and `s10r-l2` (StealthLeak2), and the three controls prove the probes. **CONCERNs recorded (not FAIL):** (a) one render-client crash in the Game Animation Sample's `AnimNode_FootPlacement` (`!PelvisTransformCS.ContainsNaN()`) on the first StealthLeak1 run `s10r-l1`, 36 frames after the newest re-open, not reproduced in 6 other runs — classified as a sample-AnimBP defect outside the fix (below); (b) the ADR-0002 estimator needs the frame's post-update server time for stamps taken in RPC bodies (fixed in the harness, finding for story 091), and its 16-sample min-delay window takes up to ~30 s to forget a server time step after a host hitch (finding for the OQ11(b) clock spike); (c) the silhouette probe is assessable only when the random city leaves the subjects in the render camera's view: 15 of 16 captures on `s10r-l1` (all ≥ 94 %) and 10 of 10 on the warm-up-off repeat (9 collapsed frames flagged), none on `s10r-l1b`; the head-bone probe covers every first visible frame of every run.

## The rig (what was built)

New scenario **`S10R`** (`Source/StealthTestHarness/Private/Scenarios/StealthHarnessScenarioS10Rerun.cpp`) on S9/S10's rule shape (grid-aligned cull deadline, explicit `Close(Relevancy)` in `TG_PostUpdateWork`, relevancy through the S9 spike hook, no forced update or forced relevancy). The original `S10` scenario is untouched, so story-005's evidence stays reproducible. Throwaway spike code; the production mechanism is IVP stories 023-025.

| ADR item | Rig implementation |
|---|---|
| S10-R2 guard | Per (subject, connection) pending-close entry, made only when the channel is `Closing` right after `Close()` (else `CloseNotSent`); the relevancy hook returns false while a non-stale entry exists; acknowledgement read **every server frame** in the cull tick from the slot (`Channels[ChIndex] != ClosedChannel`, or same object no longer `Closing`); no forced update at release. |
| S10-R3 timeout | `ReopenAckTimeoutMs` 350 (harness setting); at expiry the entry turns stale (still watched), the pair is flagged unverified; the flag clears `2 × ReopenAckTimeoutMs` after the stale entry's acknowledgement or at the pawn's next close to that connection. |
| S10-R4 repair | Client: `AStealthCharacter::OnActorChannelOpen` spike hook (count, `LastOpenChIndex`, NetGUID); a network destroy with count ≥ 2 queues a probe; the next client frame sends `NMT_ActorChannelFailure(LastOpenChIndex)` only if that slot holds an open, not-`Closing` actor channel for the same NetGUID and the connection and control channel are open. | S10-R6 clock | `UStealthSpikeClockComponent` (`Spikes/Visibility/StealthSpikeClockComponent.*`): ADR-0002 §9 exactly — owner-only unreliable ping/pong, 0.5 s cadence for 5 s then 2 s, server rate limit 4/s, NTP four-timestamp form, last 16 samples, minimum-delay offset, slew ≤ 50 ms/s, step only at first sync or > 250 ms, synced after 5 samples. Presentation reads only it (`reopenPresent`/`warm applied` records carry the estimate and its QPC instant). |

The rig waits for Round `Active` + 35 s before cycling (see the clock section). |

## Clock (S10-R6, S10-R7 (7))

- Pose/death evaluation error (estimator time used − true server time at the evaluation's QPC instant, true time from the server's frame-start pairs): see the table. Death fast-forward uses the same estimate, so its error is the same series.
- **Finding 1 (story 091, ADR-0002 §9 "E8"):** RPC bodies run in `TickDispatch`, before `UWorld::Tick` adds the frame's `DeltaSeconds` to `TimeSeconds` (`LevelTick.cpp`: `BroadcastTickDispatch` precedes `TimeSeconds += DeltaSeconds`). The literal `ServerNowPrecise = TimeSeconds + (now − frame start)` therefore stamps T2 one frame early inside `ServerClockPing`; the first gate attempt `s10r-l1-clockbias` measured a −8.7 ms bias and pose-error p95 16.5 ms (> 15). The harness now anchors the precise clock after the frame's time update (`TimeSeconds − FApp::CurrentTime`, constant while `DeltaSeconds` is the frame-start difference): bias ≈ 0, p95 ≤ 10.7 ms. The production estimator must do the same.
- **Finding 2 (OQ11(b) clock spike):** a listen-host hitch longer than `MaxUndilatedFrameTime` (0.4 s: the Round `Active` entry rebuilds the crowd, 0.6-1.3 s) clamps `DeltaSeconds`, so server time steps ~30 ms against the platform clock; the 16-sample minimum-delay window keeps the pre-step sample for up to its 32 s span, so the estimate stayed 24-39 ms off for ~25 s (dev run `s10r-dev8`). The gate runs start cycling at `Active` + 35 s, so the measurement is steady-state; the reconvergence time is the spike's to decide (e.g. reset the window on a server-time discontinuity).

## Parity (S10-R7 (5))

IVP F2 classifier: logistic regression on per-re-open features (hold, timeout, repair, `G`, warm-up frames), 2-fold cross-fit over 30 s blocks, cluster-bootstrap SE (2,000 resamples). Sanity: a synthetic +40 ms on every player `G` is detected (AUC 0.88-0.99). Per-feature KS descriptive only. Results in the table; per-run JSON `parity`, `paritySanityShift40ms`, `ksDescriptive`.

## First visible frame (S10-R7 (3))

- Head-bone probe on every client: every first visible frame of every instance (subjects, the other 26+ crowd pawns, the client's own pawn, initial spawns and re-opens) is posed: head ≥ 94 % of the standing reference (147.8 cm) for living pawns, head-to-root ≥ 99 % of the dead reference for case-B bodies (every gate and control run with the warm-up on). 0 `WarmupTimeout`. Every warm-up completed in the apply frame (the hidden mesh's bone finalisation fires under `AlwaysTickPoseAndRefreshBones`), so the first visible frame is the spawn frame: no added latency.
- Silhouette on the render client (screenshots, column diff against the culled frame, threshold 10/255: TSR history fades a newly visible primitive in over ~3 frames, so a higher threshold measured opacity, not height): see the table; strips `production/qa/evidence/story-056-…/strips/`, lead-signed sheet `production/qa/evidence/s10-rerun-frame-evidence.md`.
- 57 re-opens of one AI subject in `s10r-l2` had no visible frame on any client: it stood in a bush for one 50 s slot and the prototype's concealment latch hid its mesh (hidden = latch OR not warm, as specified); they are excluded from `G` and counted, not lost (census present).

## CONCERN (a): render-client crash in `s10r-l1`

C3 (rendering) asserted `!PelvisTransformCS.ContainsNaN()` in `AnimNode_FootPlacement.cpp:1258` (Game Animation Sample AnimBP, AnimationWarping plugin) on a background anim worker at 350 s. The newest re-open on C3 was 36 frames earlier and completed its warm-up in its first frame; at the crash frame no instance was in warm-up mode (all at the tier setting `AlwaysTickPose`, i.e. the baseline evaluation path). C1/C2 (no rendering, no per-frame evaluation) never crashed; 6 other runs (≈ 4,000 render-client minutes of pawn evaluation) did not reproduce it; S10's baseline runs never hit it either. Classified as a sample-AnimBP NaN outside the fix (the production AnimBP replaces it, ADR-0013); recorded for the production re-proof (stories 027/044) and as a risk; the gate's StealthLeak1 run is the clean repeat `s10r-l1b`.

## Limits

- Prototype pawn (`BP_CrowdCharacter` on `AStealthCharacter` on `AStealthPawn`) and the sample AnimBP; production re-proof with the production AnimBP and registries: stories 024/027/044 (unchanged).
- One machine, emulated Bernoulli loss, 3 clients, Development editor binary; player-possessed subjects are server PlayerControllers without a connection (replication-identical to the host's player), not remote humans.
- The warm-up's external tick-rate control is set but the sample mesh runs without URO, so "rate 1" is trivially met; ADR-0013's subsystem is not in the prototype.
- Fault injection drops whole packets of one connection for one frame; other bunches in that packet are resent once (natural-loss shape).
